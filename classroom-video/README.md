# STEP 教室間ビデオ通話 v0.3.1

Fire HD 8やAndroid端末を、1タップで固定ルームにつなぎます。端末はAPK初回起動時に自動登録され、映像・音声はWebRTC P2P、端末認証・シグナリング・呼び出し通知はCloudflare Worker / Durable Objectを使用します。

- 本番URL: `https://step-classroom-video.stepkobetsu.workers.dev/`

## v0.3.1に含む機能

- ログイン・会議コードなしの「教室をつなぐ」ボタン
- 固定APKの初回起動だけで、端末固有ID・専用credential・`STEP端末N`表示名を自動発行（ID・トークン・設定QRの入力不要）
- v0.3.0以前の端末は上書き更新後の初回起動で旧表示名を引き継ぎ、新しい端末固有credentialへ自動移行
- `jinryo-phone-1` のような追加端末IDと「管理者スマホ」など任意の表示名に対応（IDは校舎名から始め、重複させない）
- 呼び出しボタンから現在オンラインの端末を1台選び、その端末だけを鳴らす個別呼び出し
- 参加端末ごとに独立したPeerConnectionを持つmesh接続と複数映像の同時表示
- Fire WebView向けにICE状態を併用し、切断判定へ12秒の猶予を設けた安定化処理
- 端末ID順でoffer生成側を固定し、再接続時のoffer衝突を防止
- `event.streams`が空の旧WebViewでもremote trackから映像を組み立てる互換処理
- 設定画面からWebSocket、presence、各Peerのsignaling／ICE／接続状態を確認できる診断表示
- 「呼び出す」から現在オンラインの端末を1台選び、その端末だけを鳴らす個別呼び出し
- 既存の神領1〜3／大手町1〜3に加え、追加端末IDと自由な表示名に対応
- 自端末だけを赤丸付きで表示し、相手映像のラベルには赤丸を付けない識別表示
- 終了時にPeer、candidate、WebSocket世代、再接続タイマーを完全に破棄する再参加安定化
- pointer／touch両方に対応した下スワイプ即時非表示と、操作バータイマーの単一管理
- 接続映像だけを表示し、離脱・接続失敗時には映像を即時消去して空き枠を残さないレイアウト
- 相手1台は全画面、2台以上は選択した相手を全画面・残りを右下の小窓に表示し、小窓タップで切り替え
- 右上の接続状態横に、中央の大画面で表示中の教室名を表示
- 通話画面のタップまたは上スワイプで操作バーを再表示
- 終了ボタンのダブルタップで現在のAndroidタスクを破棄してAPKを起動し直し、トリプルタップで通話資源を解放して完全終了
- 既存端末は神領校 `jinryo-1`〜、大手町校 `otemachi-1`〜。追加端末は `jinryo-phone-1` など教室prefix付きの重複しないIDを使用し、表示名は自由設定
- APKのSharedPreferencesによる設定永続化、QRディープリンク、旧IDの自動移行
- 横向きimmersive fullscreen、標準5秒で隠れるオーバーレイ操作バー、下スワイプによる即時非表示
- 操作バーの表示時間（3／5／8／10／15秒／常時）、タブレット表示名、自分映像の表示を通話中の設定画面から変更・保存
- マイク／カメラのON/OFF
- 相手がカメラまたはマイクをOFFにした際の「ビデオ OFF」「マイク OFF」表示。中央映像のマイクOFFは右上の接続状態直下にも表示し、意図的な両方OFFを受信フリーズと誤判定しない監視
- マイク状態に依存しない穏やかな呼び出し音、画面表示、確認応答、10秒クールダウン。APKでは通話のメディア音量と分離したアラーム音量を使用
- Wi-Fi瞬断、WebSocket・WebRTC切断時の自動再接続（1〜15秒の指数バックオフ）
- `getStats()` の受信バイト数・デコードフレーム数を5秒ごとに監視し、18秒停止時にICE再接続、復旧しなければAPKを完全再起動
- WebSocketの25秒pingとpong応答を監視し、55秒以上応答がない半開接続をAPK再起動で復旧
- Fireで8秒以上バックグラウンドに移動してから復帰した場合、古い通信状態を捨ててAPKを完全再起動
- 自動再起動はオンライン時のみ、かつ60秒に1回までとして再起動ループを防止
- 受信停止を検知した時点で古いvideoの`srcObject`とタイルを消去し、最後のフレームを残さない
- ホーム画面と6時間後の休止画面ではカメラ・マイクを停止した軽量待受へ移行し、ほかの端末が接続すると操作なしで自動参加
- 切断済みWebSocketをpresenceと送信対象から除外し、端末再接続時にもシグナリングを継続
- Wake Lock と Android `FLAG_KEEP_SCREEN_ON`
- 5〜12時間から選べる連続動作時間（標準6時間）と、終了後にカメラ・マイク・WebRTCを解放する休止画面
- 休止状態と終了予定時刻を端末に保存し、待受中にほかの端末が参加した場合は新しい運転として自動復帰
- 端末固定トークン、15分の署名済み接続チケット、HTTPS、秘密情報をリポジトリに保存しない構成
- PWAとFire OS用APKラッパー（同じ画面・同じバックエンド）

## Cloudflareへ配置

Node.js 22以降で実行します。

```bash
cd classroom-video
npm ci
npm test
npm run check
npx wrangler secret put DEVICE_TOKENS
npx wrangler secret put SESSION_SECRET
npx wrangler secret put ICE_SERVERS_JSON
npx wrangler secret put TURN_KEY_ID
npx wrangler secret put TURN_KEY_API_TOKEN
npx wrangler deploy
```

`DEVICE_TOKENS` は次の形式です。各トークンは `openssl rand -hex 32` 等で個別に生成し、再利用しません。

```json
[
  {"id":"jinryo","name":"神領校","token":"64文字以上のランダム値"},
  {"id":"otemachi","name":"大手町校","token":"別の64文字以上のランダム値"}
]
```

`SESSION_SECRET` も32バイト以上のランダム値にします。本番ではCloudflare TURNキーのIDを `TURN_KEY_ID`、APIトークンを `TURN_KEY_API_TOKEN` に保存します。Workerが認証済み端末ごとに有効期間13時間の短期ICE資格情報を生成し、長期TURNキーを端末へ渡しません。ブラウザでタイムアウトしやすい53番ポートはWorker側で除外します。

`ICE_SERVERS_JSON` は緊急時の代替TURN設定用で、本番のCloudflare TURN利用時は `[]` を設定します。別TURN事業者へ切り替える場合の形式:

```json
[{"urls":["turn:turn.example.jp:3478?transport=udp","turns:turn.example.jp:443?transport=tcp"],"username":"端末用ユーザー","credential":"秘密値"}]
```

TURNなしでも同一Wi-Fiや一般的なNAT間では接続できますが、異なる回線で確実につなぐ完成条件にはTURNが必要です。TURN転送量には利用料金がかかる場合があります。設定後、UDPを遮断した回線でも `relay` candidate で映像・音声が継続することを確認してください。

## 端末への設定（自動）

1. 固定URLからAPKをインストールする。
2. アプリを初回起動する。Workerが端末固有ID、専用credential、`STEP端末N`の表示名を自動発行する。
3. カメラとマイクを許可し、「教室をつなぐ」を押す。
4. 必要なら設定画面で表示名だけを変更する。内部端末IDは変更しない。

端末別設定QR、端末ID入力、長いトークン入力は不要です。インストールIDと登録情報はAPKのSharedPreferencesへ保存されるため、上書き更新後も維持されます。v0.3.0以前の設定を持つ端末は、初回起動時に旧表示名を引き継いで新しい専用credentialへ自動移行します。公開APKには共通マスタートークンを埋め込まず、登録APIにはIP単位の回数制限と全体上限を設けています。

## APKへ切り替える場合

`android/app/build.gradle` の `APP_URL` は本番Worker URLに固定済みです。GitHub Actionsの **Build classroom video** からAPKを取得します。正式配布時は組織のkeystoreでrelease署名し、keystoreとパスワードはGitHub Secretsで管理してください。Fire端末では「不明なアプリのインストール」を一時的に許可してAPKを導入し、導入後は許可を戻します。

APKを標準運用とします。全画面・横向き固定・通話中の画面点灯維持・戻るキー無効化に加え、WebViewのlocalStorageが消えてもSharedPreferencesから端末設定を復元します。WebViewは設定したWorkerと同一originへの遷移だけを許可し、カメラ／マイク権限もそのoriginの必要なリソースだけへ限定します。呼び出し音は `STREAM_ALARM` で再生し、アラーム音量が低い場合だけ最大の80%へ一時的に上げ、4.2秒後に元の値へ戻します。おやすみモードや端末ポリシーによる拒否は突破しません。

## 5〜12時間の実機受け入れ試験

各端末を給電し、バッテリー最適化対象外にして次を記録します。

1. `jinryo-1`、`jinryo-2`、`otemachi-1`の3台で接続し、3台すべてで相手2映像が同時表示されることを確認する。映像・音声、マイクOFF、カメラOFF、各方向の呼び出しと確認も確認する。
   - メディア音量を小さくした状態と0に近い状態で、アラーム系の呼び出し音が聞こえること。
   - アラーム音量を低くして呼び出し、実用的な音量で鳴った後に元のアラーム音量へ戻ること。
   - おやすみモード等で音が禁止される場合も、大きな呼び出し表示・穏やかな点滅・確認ボタンが残ること。
2. 30分後、片方のWi-Fiを20秒OFF→ON。操作なしで「接続済み」に戻り、音声・映像も戻ることを確認。
3. 2時間後と4時間後にも同じ瞬断試験を行う。
4. 標準6時間で開始し、到達時にカメラ・マイクの利用表示が消え、「休止中」の軽量待受へ移ることを確認する。待受端末だけが相手一覧へ表示されないことも確認する。
5. 1台だけで「教室をつなぐ」を押し、ホーム画面または休止画面の残り2台が操作なしで自動参加し、新しい6時間タイマーが始まることを確認する。
6. 必要に応じて5時間と12時間の設定保存も確認し、画面消灯、音声停止、映像固着、端末過熱、メモリ不足による終了がないことを記録する。
7. Cloudflare Workers Logsで認証失敗や例外を確認。トークンやチケットそのものはログへ記録しない。

ブラウザ版とAPK版を同じ条件で各1回実施し、停止回数が少ない方を採用します。重大停止が1回でもあれば合格にせず、発生時刻、画面状態、Wi-Fi状態、端末温度、呼び出し音の有無、復旧操作を残します。

## 現時点の制約

- 自動テストは認証・署名とビルド整合性までです。Fire HD 8実機3台のカメラ、回線、5〜12時間連続運転は現地での受け入れ試験が必要です。
- 追加端末IDは作成できますが、同時表示台数が増えるほど端末負荷と通信量が増えます。4台以上の同時映像は実機評価し、必要ならSFUへの移行を検討します。
- `ICE_SERVERS_JSON` の固定TURN資格情報は認証済み端末へだけ返しますが、端末から抽出可能です。本番ではTURN事業者の短期資格情報を推奨します。
