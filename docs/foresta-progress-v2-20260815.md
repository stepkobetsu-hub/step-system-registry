最終確認日: 2026-08-15
状態: 本番運用
台帳ID: `foresta-progress-v2`

## 1. このシステムの目的

学校授業を先取りする通常授業用の進捗管理アプリです。生徒・講師・管理者が同じ入口を利用し、役割に応じた画面を表示します。

自主学習・講習用の「ステップ＆ゴール進捗管理」とは、URL、GitHubリポジトリ、Apps Script、保存先がすべて別です。改修時に混同しないでください。

## 3. 全体構成

```text
利用者のブラウザー
  └─ GitHub Pages（画面）
       └─ Apps Script Web API（認証・読込・保存）
            ├─ 専用保存シート（このアプリが書き込む正本）
            ├─ 生徒マスタ／時間割マスタ（読み取り）
            ├─ 講師マスタ（読み取り）
            └─ 成績管理API（定期テスト・学校日程の参照）
```

- 画面はGitHub Pages、処理はApps Script、運用データは専用Google Sheetに分離されています。
- 生徒・時間割・講師・成績の既存データは参照のみです。
- 授業、進行単元、CT、宿題、目標点、コメント、注意事項などは専用保存シートへ保存します。
- フロントエンドのAPI待ち時間は20秒です。

## 8. ログインとセッション

- 生徒: 生徒ID＋生徒パスワード。
- 講師: 講師ID＋講師パスワード。入力後すぐ講師画面へ進みます。
- 管理者: ログイン欄の下にある管理者入口を押し、講師ID・講師パスワードで別途再認証します。
- 共用端末: セッションは8時間。
- 個人端末: セッションは30日。
- 管理者: 明示的にログアウトするまで保持する設計です。
- ブラウザーにパスワードは保存せず、発行済みセッショントークンだけを保持します。
- サーバー側はScript PropertiesにトークンのSHA-256ハッシュをキーとしてセッションを保存します。

## 9. 現在の主要機能

### 生徒画面

- 進行表、学校進度、テスト範囲、必要ペース、宿題、目標点、5科目の定期テスト履歴を表示。
- 国語・英語・数学の進行表を科目別に開きます。
- 宿題は生徒本人のチェックと講師確認を別に管理します。

### 講師画面

- 教室・学年・氏名／読みから生徒を検索。ひらがな・カタカナ・ローマ字に対応し、文字入力または教室・学年変更から250ミリ秒後に自動検索します。検索ボタンはありません。
- 選択した複数生徒をタブで高速に切替。×で外すときは確認を表示。
- 「担当講師」を表示し、「進行表を開く」から当日の授業を入力。
- 各単元に今日の日付の追加・解除、学校現在地の保存、単元グループの一括選択を配置。
- 同じ単元を複数回扱った日付も履歴として保持。
- 指導上の注意事項を目立つ色で表示。
- 保存中表示と二重送信防止、保存済み授業・宿題の訂正機能を実装。

### 管理者画面

- 管理者ログイン後の上部に「進行表・テスト範囲設定」を大きく表示。
- 管理者画面の検索窓は全在籍生徒を対象とし、選択するとその生徒の管理者詳細を直接開きます。
- 「本日の速報」の絞り込みは、当日の予定生徒ではなく全在籍生徒から選択肢を作ります。教室は神領・大手町、学年は中1・中2・中3、学校は登録済みの全学校を表示します。
- 学校→学年→国語／英語／数学→次回テスト→予想／決定の順に選択。
- 進行表上の単元をチェックボックスで複数選択して保存。
- 学校・テスト日程登録へ直接移動。
- 英語教科書の例外設定は通常非表示。
- 本日の速報、全在籍生徒、特訓部屋、生徒詳細、注意事項・コメント・履歴を管理。

## 10. 科目別の重要ルール

### 英語

- `Part1` だけでは区別できないため、章・UNITを含めた `2-Part1` などで表示します。
- プレステップは項目ごとに分割せず、「プレステップ」という一つのまとまりとして扱います。
- 通常の宿題候補は「KeyWords 日→英」「exercise 暗記マーク」「Try赤×直し」「exercise」「宿題の赤×直し」です。
- `KEY WORDS TEST` 単元の宿題は「巻末のKeyWordsTestの暗記」だけです。TRY赤×直しとexerciseは出しません。

### 数学

- 通常の宿題候補は「TRY赤×直し」「exercise」「宿題の赤×直し」です。
- 単元のまとまり単位で選択・解除できます。

### 国語

- 進行表は中1～中3を作成済みです。
- CT／クリアテストは表示・保存しません。
- TRY赤×直し、exerciseなどの定型宿題はありません。
- 講師が各単元の「その他」欄へ入力した内容だけを宿題として保存します。

## 13. 修正・公開手順

### 画面だけを直す場合

1. `foresta-progress-v2` の `main` を最新にする。
2. `index.html`、`styles.css`、`app.js`、`domain.js`、`config.js`の必要箇所を修正する。
3. `npm test` を実行し、全テスト成功を確認する。
4. `main` へ反映する。
5. GitHub Pagesの公開処理が成功するまで待つ。
6. 本番URLを新しいタブで開き、更新識別用クエリを付けて古いキャッシュを避ける。

### APIや保存処理を直す場合

1. GitHub正本の `apps-script/Code.gs` と `apps-script/appsscript.json` を先に修正する。
2. `npm test` を実行する。
3. Apps Scriptプロジェクトへ同じ内容を反映する。
4. 新しいバージョンを作り、既存のデプロイIDを更新する。新規デプロイにしてURLを変えないことを優先する。
5. APIのGETとPOST `health` を確認する。
6. `config.js` のAPI URLと本番デプロイURLが同じか確認する。
7. 生徒・講師・管理者の順に、実際の本番URLから表示を確認する。

### 単元マスタを直す場合

1. 元の進行表と件数を確認する。
2. 専用保存シート「単元マスタ」をバックアップする。
3. 単元IDを不用意に変えず、既存の授業・宿題・範囲との参照を保つ。
4. 国語を更新する場合は `data/japanese-units.json` も同時に更新する。
5. 学年・科目・教科書／進行タイプ別の件数と表示順を確認する。

## 15. 障害時の切り分け

| 症状 | 最初に確認する場所 |
|---|---|
| 全画面で `Failed to fetch` | WebアプリAPIを直接開く、デプロイ権限、`config.js`のURL |
| 画面が古い | GitHub Pagesの公開結果、ブラウザーキャッシュ、更新識別用クエリ |
| 生徒が検索に出ない | `☆マスタ` B列の在籍値、F列の読み、H/K/P列 |
| 受講科目や英数レベルが違う | `時間割マスタ` E～AB列、AO列、AP列、受講科目キャッシュ更新 |
| 管理者へ入れない | `講師マスター` D列、AJ列、AK列、同じ講師IDでの再認証 |
| テストが選べない | 成績管理側の学校・テスト日程、学校名・学年の表記、日程キャッシュ |
| 単元が出ない | 単元マスタの科目・学年・教科書／進行タイプ・表示順 |
| 保存できない | APIのレスポンス、セッション期限、対象シート名・見出し、Apps Script実行履歴 |

復旧時は、まずGitHubの直前正常コミットとApps Scriptの直前正常バージョンを確認します。フロントだけ戻すのか、APIも戻すのかを分け、保存シートは削除や全置換をせずに復旧してください。

## 16. セキュリティと引継ぎ上の注意

- GitHub、システム台帳、スクリーンショットへ実在のID・パスワード・セッショントークンを記録しない。
- 生徒名、講師名、メールアドレスなどの個人情報を公開資料へ追加しない。
- Apps Scriptの実行ユーザーはデプロイ者、アクセスは全員です。API側の認証・権限確認を外さないでください。
- メール通知は初期値 `SUPPRESS` です。実送信へ変更する前に、通知先、重複防止、テスト方法を確認してください。
- この台帳のURL・ID・バージョンは、デプロイや保存先を変更した同じ日に更新してください。
