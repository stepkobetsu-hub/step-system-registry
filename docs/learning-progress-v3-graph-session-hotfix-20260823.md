# ステップ＆ゴール進捗管理 V3 グラフ表示・更新時ログイン維持 修正記録

更新日: 2026-08-23

## 対象

- 本番URL: https://step-progress-api.stepkobetsu.workers.dev/
- Worker: `step-progress-api`
- 正式本番ブランチ: `agent/step-progress-v3-implementation`
- 現在確認済み本番Version: `4e606d3b-e034-443c-8727-36a28fea52bc`

## 症状

- 宿題一覧はすぐ表示されるが、進捗グラフが数分〜10分待っても出ないことがあった。
- ブラウザ更新時にログイン画面へ戻されることがあった。
- 高速表示対策後、一時的に「全体進捗」グラフが2個表示された。

## 原因

- `getStudentDashboard` 自体は概ね1秒前後で返っており、D1集計速度が主因ではなかった。
- グラフ用データ取得と実際の描画タイミングが分離しており、後続描画待ちが発生していた。
- キャッシュ済みダッシュボードがある場合に、再取得せず、かつキャッシュから即描画しない経路があった。
- 更新時にアプリ内の有効な保存済みセッションより古い共通セッションを先に確認する経路があり、更新でログイン画面へ戻ることがあった。
- 当初の修正が別ブランチ側だけにあり、正式本番Workflowが `agent/step-progress-v3-implementation` から再生成した際に高速化・セッション維持修正が上書きされた。
- 高速表示用の仮グラフが通常グラフ描画後も残り、グラフが2重表示された。

## 恒久対策

- 正式本番ブランチに `cloudflare/scripts/apply-v3-graph-session-fix.mjs` を追加し、正式復旧Workflowから毎回適用する。
- 新規取得時は `getStudentDashboard` の返却直後に上部グラフを即描画する。
- キャッシュ済みの場合も更新直後に上部グラフを即描画する。
- 古い/壊れたダッシュボードキャッシュは破棄して再取得する。
- 有効な `fsSession` / `forestaProgress.rememberedSession` を古い共通セッションより優先する。
- 明示的なログアウトは `forestaProgress.manualLogout` で従来どおり尊重する。
- 高速表示用仮グラフは通常グラフ完成時に自動削除し、2重表示を防ぐ。
- 宿題表示・宿題保存データ、進捗データ、目標データにはこのUI修正で変更を加えない。

## 本番実ブラウザ確認

田中彗翔（1100）を短時間の保護された検証セッションで本番Chromium確認。ユーザーのパスワードは使用していない。

- 更新1回目: `173%` 表示1個、`121/70` 表示1個、ログイン画面へ戻らない
- 更新2回目: `173%` 表示1個、`121/70` 表示1個、ログイン画面へ戻らない
- 直近検証時間: 約2.0秒 / 約1.4秒（1.2秒の二重表示確認待ちを含む）
- 本番health: 生徒34 / 進捗3,540 / 目標6,555 / 宿題2,271

## 今後の注意

本番UIを再生成・復旧するときは必ず `agent/step-progress-v3-implementation` の `apply-v3-graph-session-fix.mjs` を通すこと。別ブランチだけにUI修正を置かない。グラフ高速化の仮表示を追加する場合、通常表示完成後の削除処理を必ずセットで確認する。
