# 証憑自動回収アプリ 引継ぎ・複数PC運用

最終更新: 2026-08-23  
対象: 株式会社エデュクレスト 経理業務

この文書は、自宅PCと塾PCのどちらからでも証憑自動回収アプリの保守・サービス追加を続けられるようにするための引継ぎ正本である。公開してよい仕様だけを記録し、ログインID、パスワード、2段階認証コード、カード情報、Cookie、認証トークン、取得PDFは記録しない。

## 現行版

- Windows本番版: v1.5.2
- 配布物: OneDriveの `証憑自動回収アプリ/証憑自動回収アプリ_新しいPC用_v1.5.2.zip`
- 起動方法: 各Windows PCのデスクトップにある「証憑自動回収」アイコン
- 保存先: `証憑自動回収/YYYY年/MM月/サービス名/`
- 配布ZIPと取得PDFは公開GitHubへ置かない

## 対応サービス

1. Amazon.co.jp: 「領収書等」から開く「印刷可能な注文概要」をPDF化
2. 中部電力ミライズ「ビジエネ」: 対象4契約の「ご使用量のお知らせPDF」
3. Render: Billing / Invoice Historyの請求書PDF
4. テレワープ: 2契約のお支払い履歴にある領収書PDF
5. SPRIX: Foresta Orderの請求書一覧にある「ご請求書」PDF
6. ChatGPT: 支払い管理の請求履歴にあるStripe領収書PDF

各サービスは対象年月を指定し、PDF本文が正しい書類種別・対象年月であることを確認してから成功とする。同じ注文番号、契約、請求書番号、領収書番号は重複保存しない。

## 実動確認

- SPRIX: 2026年7月分の請求書1件を取得し、PDF内容・請求日・請求書番号・金額を検証済み
- ChatGPT: 2026年7月分の領収書7件を取得し、OpenAIの領収書、対象年月、領収書番号、金額を検証済み
- Amazonと中部電力は、利用者提供の正解見本と同じ書類であることを基準にする

## 保留中

### TCカード（MY TS CUBIC）

- ログインとメール認証まで確認済み
- 「過去のご利用明細（PDF）一覧」へ進む際、カード有効期限とセキュリティコードによる追加認証が必要
- カードが手元にないため、PDF一覧・ダウンロード確認とアプリ実装は保留
- カード有効期限、セキュリティコード、認証コードはアプリ、ソース、台帳、ログへ保存しない

## 自宅PCと塾PCで続ける方法

1. 新しいPCで同じOneDriveアカウントへログインし、`証憑自動回収アプリ` フォルダを開く。
2. `証憑自動回収アプリ_新しいPC用_v1.5.2.zip` を右クリックして「すべて展開」する。
3. 展開先の `デスクトップに設置して起動.cmd` を1回実行し、デスクトップアイコンを作る。2回目からはそのアイコンだけで起動する。
4. ログインセッションはPC間でコピーしない。各PCで利用者本人がパスワード、2段階認証、カード追加認証を入力する。
5. アプリのソースと本引継ぎ文書は、公開ではないGitHubリポジトリまたは会社管理の非公開保管先で同期する。公開台帳には秘密情報を含めない。
6. 取得PDFは公開GitHubへ置かない。当面は月次回収を行う主PCを1台決め、別PCで同じ月を重複回収しない。
7. 取得PDFをPC間で共有する場合は、会社管理の非公開OneDrive等を使う。共有前に保存権限と個人情報の取扱いを確認する。
8. 塾PCのCodexで続けるときは、同じプロジェクトフォルダを開き、本書と `SYSTEM_REGISTRY.md` を最初に読ませる。ローカルファイルはPCごとに用意する。

## 塾PCでCodexへ渡す開始文

```text
証憑自動回収アプリの続きです。
最初に step-system-registry の docs/evidence-collector-handoff.md と SYSTEM_REGISTRY.md の「証憑自動回収：本番仕様」を読んでください。
現行版はv1.5.2です。秘密情報・取得PDF・認証セッションを公開場所へ保存しないでください。
今回追加したいサービスは（サービス名）です。実際の正解PDFと画面を確認してから実装してください。
```

## 新しいサービスを追加するときの記録項目

- サービス名と正式ログインURL
- 認証方法（ID・パスワード、Google/GitHubログイン、2段階認証等）
- 対象年月の選び方
- 正解となる請求書・領収書PDFの実物見本
- PDFを開くまでのボタン名と画面遷移
- PDF本文で検証する見出し、日付、金額、番号
- 保存ファイル名の形式
- 重複判定に使う番号
- 1件失敗した場合の再試行単位
- 実動確認した年月・件数
- 未確認・保留事項

## 更新時の完了条件

1. 対象サービスだけの回収が成功する。
2. 正解PDFを実際に1件以上取得し、本文と対象年月を検証する。
3. 同じPDFを再実行しても重複保存しない。
4. 失敗理由を日本語で表示し、他サービスの処理を止めない。
5. デスクトップのアプリを最新版へ更新する。
6. 本書、`SYSTEM_REGISTRY.md`、資産管理台帳の画面表示を更新する。
7. 秘密情報・個人情報・取得PDFが公開GitHubへ含まれていないことを確認する。
