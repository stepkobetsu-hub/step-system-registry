## 生徒トップ進捗グラフ高速化・更新時ログイン維持（2026-08-23）

### 発生した症状

- 宿題一覧はすぐ出るが、進捗グラフだけ長時間表示されないことがある。
- 田中1100では10分待ってもグラフが出ない報告があった。
- ブラウザ更新をするとログイン画面へ戻されることがあった。
- 一度グラフが出ても、2回目の更新でグラフが出ない経路があった。

### 原因

1. `getStudentDashboard` 自体は田中1100で概ね1秒前後で返っており、D1集計が主因ではなかった。
2. 先行読込はしていたが、レスポンス後のグラフ描画が後続の画面処理を待つ経路が残っていた。
3. ダッシュボードキャッシュがある2回目以降の更新では再取得を省略する一方、キャッシュから上部グラフを即描画していなかった。
4. 更新時にアプリ自身の有効な保存済みセッションより共通生徒セッションを先に確認するため、共通側が古い場合にログイン画面へ戻る経路があった。

### 対策

- D1の `getStudentDashboard` が返った瞬間に `renderProgressHeroFast_()` で上部進捗グラフを先に描画する。
- `state.dashboardCache` が既にある場合も、更新直後にキャッシュから上部グラフを即描画する。
- 更新時は、有効な `fsSession` / `forestaProgress.rememberedSession` を共通生徒セッションより優先する。
- 有効なアプリ内セッションがある限り、古い共通セッションを理由にログイン画面へ戻さない。
- 宿題表示・宿題保存処理は変更しない。

### 本番実ブラウザ確認

現在本番 Version `c11aea67-e30f-441d-a7c0-e1fe8ca50583` を、短時間の保護された検証セッションでChromiumから確認した。ユーザーのパスワードは使用していない。

田中彗翔1100で、有効な保存済みセッションに加えて意図的に古い共通セッションを残した状態から2回連続で更新した。

- 正式URL 1回目: **1.177秒**
- 正式URL 2回目: **0.251秒**
- キャッシュ回避URL 1回目: **1.121秒**
- キャッシュ回避URL 2回目: **0.233秒**
- いずれもログイン画面へ戻らず、`173% (121/70)` を表示

正式URLとキャッシュ回避URLの配信HTML SHAは同一で、両方に保存済みセッション優先処理・キャッシュ済みグラフ即描画処理が含まれることを確認。CloudflareのHTMLレスポンスは `cache-control: public, max-age=0, must-revalidate` で、確認時点では古いHTMLの取り違えは再現しなかった。
